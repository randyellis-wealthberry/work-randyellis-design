### ⚠️ Constraint — read before implementing

This is a Tailwind **v4** project (`@import "tailwindcss"` in `app/globals.css`). Tailwind v4 no longer auto-detects `tailwind.config.js`; a JS config only applies if loaded via `@config "../tailwind.config.js"` in the CSS entry file. **`app/globals.css` has no `@config` directive**, so `tailwind.config.js` is dead code. Concretely, for this phase:

- Do **not** use `bg-primary`, `bg-card`, `bg-secondary`, `text-muted-foreground`, `bg-accent`, etc. — these map to `hsl(var(--x))` custom properties that are declared in the unused `tailwind.config.js` but never defined anywhere in `app/globals.css`. They compile to no visible styling (transparent/inherited).
- Do **not** use the custom `text-3xl`/`text-4xl`/`text-5xl`/`text-6xl`/`text-xxl` sizes from `tailwind.config.js` (48/60/72/96/40px) — they don't exist at build time. Tailwind v4 **defaults** apply instead (`text-3xl`=30px, `text-4xl`=36px, `text-5xl`=48px, `text-6xl`=60px).
- **Use literal Tailwind utility classes** (`zinc-*`, `amber-*`, default type scale) exactly as every existing bespoke project page already does (`app/projects/echo/`, `app/projects/rambis-ui/`, `app/projects/addvanced/`). This spec is written entirely in those terms so it is safe to implement as-is.
- The site's actual dominant background is applied as a literal class on `<html>` in `app/layout.tsx`: `bg-white ... dark:bg-zinc-950`. Treat that as ground truth for "dominant surface," not any `--background` token.

## Spacing Scale

Declared values (Tailwind's default scale is a strict 4px multiple system — no custom config needed):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`) |
| sm | 8px | Badge padding, chip gaps (`px-2 py-0.5`, `gap-2`) |
| md | 16px | Card internal spacing, form-adjacent gaps (`p-4`, `gap-4`) |
| lg | 24px | Feature/step card padding (`p-6`) — matches the `SpotlightCard`/`addvanced` precedent |
| xl | 32px | Grid gaps between feature cards (`grid gap-8`) — matches the `addvanced` IDI grid precedent |
| 2xl | 48px | Sub-section internal spacing (`py-12`) |
| 3xl | 64px | Page vertical padding (`container ... py-16`) — matches `echo/page.tsx` |

Exceptions:
- **Major section rhythm** (hero → features → how-it-works → screenshot → CTA): `space-y-16 sm:space-y-24` (64px → 96px) on the `<main>` wrapper. (Deliberately not copying `echo`'s `space-y-32 sm:space-y-24`, which shrinks on wider viewports — an inversion that reads as unintentional; Phase 4 uses an ascending rhythm instead.)
- **Touch targets**: CTA buttons and the grid-card badge must clear 44px minimum height on mobile (use `size="lg"` — `h-10`/40px — is under 44px; add `py-3` override or use `min-h-[44px]` on the primary/secondary CTA buttons specifically).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 (`font-normal`) | 1.5 (Tailwind default for `text-base`) |

## Color

60/30/10 split, using only classes verified to actually render (see Constraint):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-white` / `dark:bg-zinc-950` | Page background (matches `<html>` in `app/layout.tsx` — do not override per-section) |
| Secondary (30%) | `bg-zinc-50` / `dark:bg-zinc-900/50`, border `border-zinc-200` / `dark:border-zinc-800` | Feature-grid cards, how-it-works step cards, CTA closing band — matches the existing `bg-zinc-50 dark:bg-zinc-900/50` stat-block pattern in `echo-client.tsx` |
| Accent (10%) | `amber-600` (light) / `amber-500` (dark) | See "Accent reserved for" below — **this exact pairing is the Tailwind-native equivalent of D-08's OKLCH tokens** (verified: `--color-amber-600: oklch(66.6% 0.179 58.318)` and `--color-amber-500: oklch(76.9% 0.188 70.08)` in `node_modules/tailwindcss/theme.css` match D-08's light/dark values digit-for-digit). No custom CSS variable is needed — use the plain Tailwind classes. |
| Destructive | N/A | No destructive actions in this phase (static showcase page) |

**Accent reserved for** (never "all interactive elements"):
- Primary CTA button fill ("View live product ↗")
- "Live Product" badge fill (both the `/projects` grid card and the hero echo of it)
- How-it-works step-number circles (1 / 2 / 3)
- Feature-grid icon tint (6 feature icons, `bg-amber-600/10 dark:bg-amber-500/10` circle + `text-amber-600 dark:text-amber-500` icon)
- The Waffle logo mark (SVG ships with its own fixed `#f97316` fill — no theming needed, exempt from text-contrast rules as a logotype)

**Contrast rule — verified via WCAG relative-luminance math, must be followed exactly:**
- `amber-600` **text** on the white dominant background = **3.18:1** — passes the 3:1 non-text/graphical-object threshold (safe for icons and for headings ≥24px bold) but **fails** 4.5:1 for normal body/label text. Never use `text-amber-600`/`text-amber-500` for body copy, links, or the 14px Label role.
- **Any amber background fill** (button, badge, step-circle) must pair with **dark text**, not white: `text-zinc-950` on `bg-amber-600` = 6.60:1 (AA pass); `text-zinc-950` on `bg-amber-500` = 9.78:1 (AAA pass). White text on either amber shade fails (2.1–3.2:1). This applies in **both** themes — do not swap to white text in dark mode.
- Secondary CTA ("Try free") stays neutral (`variant="outline"`, zinc border/text) — accent is reserved for the primary action only, preserving the CTA hierarchy from D-03.
