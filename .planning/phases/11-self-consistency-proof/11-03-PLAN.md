## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → `/about` | Server-rendered page shipping a `"use client"` component. The awards content added here originates entirely from module-scope literals in the source file — no request data, query params, headers, CMS, database or network response reaches it. |
| repo → client bundle | The award strings are compiled into the client bundle and become publicly readable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-21 | Tampering (XSS) | `app/about/about-client.tsx` awards render | mitigate | The award strings are static module-scope literals rendered as JSX children, which React escapes; there is no user-controlled input on this path and therefore no injection source. The one way to create a sink would be `dangerouslySetInnerHTML` to get list markup out of a string — explicitly forbidden by Task 2's action and enforced by the acceptance criterion `grep -c "dangerouslySetInnerHTML" app/about/about-client.tsx` returns `0`. |
| T-11-22 | Information Disclosure | award names, issuers, categories | accept | All four awards are already published in the Person JSON-LD at `lib/seo/json-ld.ts:79-84` and served to every crawler on every page. Making them human-readable discloses nothing that was not already public. No PII, no client name under NDA, no internal metric is added — the content is Randy's own award record, sourced to a deck he authored. |
| T-11-23 | Spoofing (misrepresentation) | the Webby judge credential | mitigate | The genuine integrity risk in this plan is presenting a judging credential as a win — a credibility claim the site cannot support, on a page whose entire purpose is verifiable proof. Mitigated structurally, not by copywriting: the Webby lives in a separate `judgeCredential` field, never in the `awards` array, renders outside the `<ul>` as a non-`<li>` sibling, and its text must contain "judge" and must not contain "won" or a placement word. Enforced by three acceptance criteria in Tasks 1 and 2, and pinned permanently by plan 11-04's assertion that no `award` entry matches `/webby/i`. |
| T-11-24 | Denial of Service | `/about` render cost | accept | The change adds four static list items to one grid cell. No new network call, no new effect, no animation, no client state. Render cost is unmeasurably different. |
| T-11-SC | Tampering | npm supply chain | mitigate | This plan installs zero packages and adds zero imports — notably no icon library, which D-06 forbids anyway. Enforced by the acceptance criteria that `git status --porcelain package.json package-lock.json` outputs nothing and that the diff adds no `lucide-react` import. No `## Package Legitimacy Audit` is required because no package-manager install task exists. |
