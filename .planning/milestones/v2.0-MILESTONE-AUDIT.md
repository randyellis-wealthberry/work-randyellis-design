**Audited:** 2026-08-22

inline rather than by subagent. Checkboxes in `REQUIREMENTS.md` were treated as

## Why this audit was needed

The `/gsd:complete-milestone` pre-flight failed three checks:

1. No v2.0 milestone audit existed.
2. Phases 06, 07 and 08 had no `SUMMARY.md` files. Phases 07 and 08 have **no
   directory and no git history at all** — they were never committed. Phase 06
   has a plan and no summary.
3. `STATE.md` reported `completed_phases: 2` / `percent: 33` while `ROADMAP.md`
   marked five of six phases `[x]`.

This is the same condition v1.0 closed under — its MILESTONES entry records that
"phases 1-3 lack per-phase GSD verification artifacts (compensated by
direct-codebase audit)". The same compensation is applied here: the codebase is
the evidence, and this document is the record.

**Conclusion: this was a bookkeeping gap, not a delivery gap.** The work of
phases 06-08 shipped. The paperwork did not.

## Restated requirements — MIG-01..04

**As written**, MIG-01..04 require the four bespoke pages to render
`DecisionCallout`, `CaseStudyTOC`, `ReflectionBlock` and `RoleNarrativeSection`.
No file imports those four names.

**What actually shipped** is a superseding architecture that satisfies the same
goal more completely. All five standalone project pages — addvanced, echo,
nagarro, rambis-ui *and* waffle — import a shared
`@/components/case-study/case-study-template` plus `@/components/case-study/diagrams`,
and `/projects` shares `section-chrome`. `CaseStudyTemplate` is what renders the
decision-with-rationale arc.

The phase goal was *"all 7 in-scope case studies share one structurally
consistent pattern."* One shared template achieves that more strongly than four
separately-composed components would have, and it pulled waffle into the same
system as a bonus.

**Verdict: PASS on goal, requirement text superseded.** The archived
`v2.0-REQUIREMENTS.md` records the shipped architecture rather than the
originally-specified one, so the historical record matches the code.

## Gap carried to v3.0 — CRED-07

CRED-07 requires that no metric be invented and that the site not contradict
itself across surfaces. **Within case-study content this holds.** Sitewide it
does not.

FND-03's own deck-coverage audit returned `Unbacked` verdicts on three aggregate
figures, and all three are still live:

| Audit ID | Claim | Verdict | Source |
|----------|-------|---------|--------|
| SITE-01 | "2.5M+ Users Impacted" | Unbacked | `components/core/animated-number-basic.tsx:12` |
| SITE-03 | "$50M in product value" | Unbacked | `components/core/animated-number-basic.tsx:14` |
| SITE-04 | "800+ Designers Mentored" | Unbacked | `components/core/animated-number-basic.tsx:15` |

They propagate to `/about`, `/services`, `lib/metadata.ts` and both OG image
generators. Phase 9's `09-03-PLAN` *aligned the `$50M` wording* across surfaces —
harmonising a claim the audit had already ruled unsupported, which made the
problem harder to see because afterwards every surface agreed.

"4 Design Awards", which shares the same component, **is** backed —
`CREDIBILITY-COPY.md` §1 sources all four to deck slide 28 with issuer and
category. It must survive any remediation.

**Disposition:** accepted as known debt at v2.0 close, scoped into v3.0 as
CRED-10, CRED-11 and CRED-12 in `.planning/MILESTONE-CONTEXT.md`. Not a blocker
for archiving v2.0, because it is a v1.0-era claim that v2.0 never set out to
fix.

   and the primary conversion path on a site whose `PROJECT.md` core value names
